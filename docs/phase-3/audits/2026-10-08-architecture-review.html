Problem: moving a picture has two live index conventions (moveTokenCore for drag, moveTokenToCore for authoring.movePicture), and the follow-up — select, re-target the open panel, build a picture from a catalog entry, paste — is written in both authoring.ts and editor-drag.ts; the well-tested mutators sit below the place the bugs live.

Solution: one module takes intent (insert entry at anchor, move picture to group/anchor, copy/paste, move group) and performs mutation, selection and panel re-targeting as one step; sessionActions becomes its implementation.

  • Locality: one place owns edit follow-ups
  • Leverage: drag, keyboard, panel share one interface
  • One move convention; one deleted
  • Test the real sequence via createDocumentSession()
  • pasteToken/addTokenToSelectedStep dead paths disappear
ADR-0002: no conflict — the no-op guards stay inside setSteps/updateTokenIn, behind the new interface.

Top recommendation

1 · Picture commands, cleared by 2 · retiring legacy persistence first

Candidate 2 is pure deletion and removes the aliases and dead session actions that would otherwise be carried into the new interface; candidate 1 then puts every picture/group edit follow-up behind one interface where real call sequences can be unit-tested — the place drag, keyboard and panel bugs actually live today. Candidate 3 lands naturally on top, since its drop module returns exactly the commands candidate 1 defines.

Suggested order: 2 → 1 → 3 → 4 → 5, then 6-9 as capacity allows.
